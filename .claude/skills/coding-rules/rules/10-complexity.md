# 10: 計算量・メモリの報告義務

### PERF-1: O(N^2) 以上は必ず報告する [MUST] [構造]
- 対象: 全言語
- 規則: 時間計算量または追加メモリが入力規模 N に対して O(N^2) 以上になる実装を
  書いたら、レビューパックの準拠メモに「計算量・想定 N・許容と考える根拠」を必ず書く。
  N に固定上限があるならそれを根拠にしてよい。**黙って N^2 を書かない**
- 理由: 計算量は小さなテスト入力では見えず、実データで突然性能バグとして現れる。
  書いた本人しか計算量を把握していない瞬間に申告させるのが最も安い
- 悪い例: 全ペア比較をコメントなしで実装 / 良い例: 準拠メモに
  「照合は O(N*M) (N=行数, M=パターン数)。M は設定由来で高々数十のため許容」と記載

### PERF-2: accidental quadratic を避ける [SHOULD] [構造]
- 対象: 全言語
- 規則: ループ内の線形操作は定数時間の手段に置き換える
  (リストの線形検索 → set/dict、文字列連結 += → join/Builder、先頭挿入 → deque)
- 理由: 意図しない O(N^2) の最頻出パターン。1 行ずつは無害に見えるため
  レビューでも見逃されやすい
- 悪い例: `for x in items: if x in seen_list:` / 良い例: `seen = set()` を使う
