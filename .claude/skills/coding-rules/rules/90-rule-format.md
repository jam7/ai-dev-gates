# 90: ルールファイルの書き方 (このファイルはお手本。実ルールではない)

新しいルールは `rules/NN-<topic>.md` として追加し、git commit で共有する。
NN は読み込み順で、番号の大きいファイルが優先 (後勝ち)。
不要になったデフォルトルールは対応する `.md` を削除すれば無効化できる
(`.template.md` は原本として残る。復活させたいときはそこからコピー)。

## 書式

1 ルール 1 ブロックで書く:

```markdown
### <ID>: <一言サマリー> [MUST|SHOULD] [構造|細部]
- 対象: (言語やパス。例: C++ のみ / tests/ 以下は除外)
- 規則: (何をする / しない)
- 理由: (なぜ。レビューで「なぜダメ?」と聞かれたときの答え)
- 悪い例 / 良い例: (短く)
```

- **MUST** = 常に守る / **SHOULD** = 原則守る。外れるときは準拠メモに理由を書く
- **構造** = 既存コードと矛盾してもルール優先 / **細部** = 周囲の既存コード優先

## 記入例

### NAME-1: 単位を名前に含める [SHOULD] [細部]
- 対象: 全言語
- 規則: 時間・サイズを表す変数名は単位を接尾辞にする
- 理由: 呼び出し側の単位取り違え (秒とミリ秒など) を防ぐ
- 悪い例: `int timeout;` / 良い例: `int timeout_ms;`

### ERR-1: エラーを握りつぶさない [MUST] [構造]
- 対象: 全言語
- 規則: 戻り値のエラーコードを無視しない。処理できないエラーは呼び出し元へ伝播する
- 理由: 握りつぶしたエラーは離れた場所で別の症状として現れ、調査コストが跳ね上がる
- 悪い例: `(void)write(...);` / 良い例: エラーを返すか、無視してよい根拠をコメントで書く
