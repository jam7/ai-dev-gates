# prepare-new-chat: 新しいチャットへ引き継ぐ

`/compact` は会話を要約して**同じセッションを続ける**。新しいチャットは
**要約すら無い**代わりに、破棄した作業の記憶も持ち込まない。

このスキルの仕事は 2 つ:

1. 会話にしか無い情報のうち、**ファイルに書けるものは今すぐ書く**
2. 残り (ファイルに書く場所が無いもの) を、**新チャットの最初の発言**にまとめる

最初の発言はユーザーがコピペするので、**こちらからは新チャットを開始できない**。
文言を提示して、ユーザーに貼ってもらう。

## prepare-compact との違い

**手順 1〜2 は `prepare-compact` と同じ。** そちらの「会話にしか無い情報を
洗い出す」と「ファイルへ出せるものを出す」の節をそのまま使う
(行き先の表、実データの扱い、書いたら引数から外す原則も同じ)。

違うのは**引き継ぎ先の性質**で、それが成果物を変える:

| | `/compact` | 新しいチャット |
|---|---|---|
| 会話の要約 | 劣化した形で残る | **無い** |
| CLAUDE.md / memory の索引 | 残る | **自動で読まれる** |
| scratchpad のパス | 同じ | **変わる** |
| 作業ディレクトリ・git の状態 | 同じ | 同じ (ファイルは残る) |
| 破棄した作業の記憶 | 要約に混ざる | **持ち込まれない** |
| 成果物 | `/compact` の引数 (3〜6 行) | 最初の発言 (下記の 4 節) |

**新チャットを選ぶ理由になるのは最後の行。** 途中で方針転換して前半の作業を
破棄した場合、要約は「削除した」と「公開した」のような矛盾した記憶を運ぶ。
ファイルには結論だけが正しい形で残っているので、読み直させる方が確実。

## 手順

### 1〜2. 会話にしか無い情報を洗い出し、ファイルへ出す

`prepare-compact` の手順 1〜2 と同じ。ここでは繰り返さない。

新チャット特有の追加が 1 つある: **今のセッションの scratchpad に、後で要る物が
置かれていないか**を確認する。置かれているなら:

- 恒久的に要る物 (バックアップの bundle、退避したデータ) は、**恒久的な場所へ
  移すことを提案する**。scratchpad はセッション単位で、新チャットは別のパスになる
- 移さない判断なら、**絶対パスを最初の発言に書く**。新チャットは自力でその
  ディレクトリを見つけられない

### 3. 最初の発言を組み立てる

4 つの節で書く。**読む順序を指定するのが要点** — 新チャットには要約が無いので、
どこから読めば全体が掴めるかを教える必要がある。

1. **現在地** — 1〜2 文。何が終わって、何が未解決か。数字を入れる
   (コミット数、テストの状態、repo がクリークかどうか)
2. **まず読むファイル (順序付き)** — 各行に「何が書いてあるか」を添える。
   最初の 1 つは**全体の位置が分かるもの** (`TODO.md` の現在地など) にする。
   ファイル名だけ並べても、何を期待して読むのかが分からない
3. **次にやること** — 具体的な次の一手。**人間の手の要る部分があれば明記する**
   (でないと新チャットが勝手に進めようとする)。守ってほしい規約があれば
   ここで名指しする
4. **環境の事実** — ファイルに書けない/書くべきでないもの:
   - テストやビルドの起動方法で、既定と違うもの (環境変数、DISPLAY など)
   - PATH や導入状態のような**このマシン固有の事実**
     (公開 repo に書くと他環境で嘘になる)
   - scratchpad の絶対パス (残した物があるなら)

memory は自動で索引が読まれるが、**索引は 1 行の手掛かりしか持たない**。
今の作業で効くものは「本文まで読んでほしい」と名前で指定する。

提示するときはコードブロックに入れる。あわせて短く 2 つ書く:

- **残す理由** — 項目ごとに「なぜファイルに書けなかったか」
- **残さないもの** — ファイル済みなので落とす、と明示する

### 4. 新チャットが始まったら

そのチャットの最初の仕事は、**指定されたファイルを読むこと**。読む前に作業を
始めない。読んだ結果と最初の発言の内容が食い違っていたら、**ファイルを正とし、
食い違いを報告する** (最初の発言は書いた時点の記憶で、ファイルの方が新しい)。

## やらないこと

- 会話全体を要約しようとしない。**新チャットに要約は要らない。** 要るのは
  「どこを読むか」と「次に何をするか」
- ファイルに書ける情報を最初の発言だけに置かない (新チャットで検証できなくなる)
- scratchpad のパスを書かずに「バックアップは scratchpad にある」と書かない。
  新チャットのパスは違う
- ユーザーの代わりに新チャットを開始しようとしない (できない)
- 破棄した作業の経緯を最初の発言に詰め込まない。**破棄したこと自体が重要なら
  ファイルへ書く** (再提案を防ぐため)。最初の発言はそのファイルを指すだけでよい
