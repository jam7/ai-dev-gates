# prepare-compact: 圧縮前に、消えて困るものを外へ出す

`/compact` は会話を要約する。要約は劣化するので、**要約に頼らないのが正しい**。
このスキルの仕事は 2 つ:

1. 会話にしか無い情報のうち、**ファイルに書けるものは今すぐ書く**
2. 残り (ファイルに書く場所が無いもの) だけを `/compact` の引数にまとめて渡す

`/compact` 自体はユーザーのコマンドなので、こちらからは実行できない。
**引数文字列を提示して、ユーザーに実行してもらう**。

## 手順

### 1. 会話にしか無い情報を洗い出す

いま進行中の作業について、次を思い出す。「圧縮後の自分が知らないと困ること」だけ。

- 進行中タスクの位置 (どこまで終わり、次は何か)
- 決定した方針と、**却下した案とその理由** (再提案を防ぐ)
- 実機・実環境の値 (接続先、ポート、デバイス ID)
- 未コミット/未 push の状態と、それに関する制約
- 今日訂正した内容 (同じ間違いを繰り返さないため)
- ユーザーから受けた指示のうち、まだ効いているもの

### 2. ファイルへ出せるものを出す

出せるなら出す。圧縮引数は短いほど劣化しない。

行き先は下表を目安にするが、**そのプロジェクトが既に使っている場所が優先**。
CLAUDE.md にディレクトリ規約があればそれに従い、無ければ既存ファイルの置き方に合わせる。

| 情報の種類 | 行き先 |
|---|---|
| 設計判断・却下した案の理由 | `docs/adr/` か `docs/<feature>/design.md` の ADR ブロックなど、PJ で ADR を書いている場所 |
| 進捗・残タスク | `TODO.md` / `notes/TODO.md` / issue トラッカーなど、PJ の残タスク置き場 |
| 調査の生記録 | `notes/` 配下 (`notes/reviews/` `notes/fix-sessions/` など) |
| ユーザーの好み・繰り返し効く指示 | memory (`type: feedback` / `user`) |
| 継続中の目標・制約 | memory (`type: project`) |

置き場所が無い種類の情報なら、無理に新しいディレクトリを作らず圧縮引数に残す
(1 項目のために規約を増やすほうが後で害になる)。

**実データ (実パス・実機ログ・ホスト名) はプロジェクトの規約に従う**。
公開 repo に書かない取り決めがあるなら、圧縮引数にも書かない
(引数は会話に残り、要約経由でコミットメッセージに紛れ込みうる)。

書いたら、その項目は圧縮引数から**外す**。二重に持たない。

### 3. 引数を組み立てて提示する

形式:

- 冒頭に**現在地**を 1 文 (何のフェーズの何が終わって、次が何か)
- 次に**参照先**を 1 文 (「詳細は X と Y にあるのでそちらを読めばよい」)
- そのあとに**会話にしか無い項目**を番号付きで列挙

長さの目安は 3〜6 行。ファイルを指せるものを引数に書き写さない。

提示するときは、コピーしやすいようコードブロックに入れて 1 行で置く。
あわせて次の 2 つを短く書く:

- **残す理由** — 項目ごとに「なぜファイルに書けなかったか」
- **残さないもの** — ファイル済みなので落とす、と明示する。
  ユーザーが「あれは入れなくていいのか」と確認する手間を消す

### 4. 圧縮後

ユーザーが `/compact` を実行したら、引数に書いた次のタスクから再開する。
確認や前置きは要らない。

## やらないこと

- 会話全体を要約しようとしない。それは `/compact` の仕事
- 「念のため」で引数を長くしない。長い引数は要約の中で薄まる
- ファイルに書ける情報を引数だけに置かない (圧縮後に検証できなくなる)
- ユーザーの代わりに `/compact` を実行しようとしない (できない)
