# ADR-001: 配置先ファイルに所有者クラスを持たせ、`--force` の意味を 1 つに保つ

日付: 2026-08-28
状態: 採用

## 背景

install.sh の設計はこうだった。書く前に全配置先を調べ、差分があれば列挙して
何もせず終了する。`--force` はその差分を置き換えてよいという合図
(コミット "Add the commit gate, generalized from image-viewer")。そのとき
宣言された保持対象は `rules/*.md` と `gate.conf` などの宣言ファイル。
**`CLAUDE.md` は入っていなかった**。

CLAUDE.md を導入した時点では、既存ファイルは `[y/N]` の個別確認で
保護されていた (コミット "Add CLAUDE.md template with directory and TODO
conventions")。既定は保持で、案内は「テンプレートから必要な分をマージせよ」。
per-item の確認を廃止して 1 つの `--force` に畳んだとき、**この個別確認が
「パッケージ更新の同意」と同じフラグに吸収された**。

結果 (2026-08-28 に実測。詳細は design.md D-02):

- プロジェクト固有の CLAUDE.md は必ず「旧版」として列挙される
  (image-viewer / na の両方で確認。テンプレートとの共通行は 1 行 / 0 行)
- `--force` はそれをテンプレートで上書きする (123 行 → 28 行)
- チームがルールを 1 行編集すると、以後 `--force` なしの install は全部止まる
- したがって「hook だけ足す」が実質不可能。`--force` なしでは止まり、
  `--force` では CLAUDE.md が消える

## 決定

1. 配置先のファイルを **package / user / once** の 3 クラスに分け、
   **1 か所の表で宣言する** (design.md D-01)
2. **衝突検出と書き込みは同じ表を読む** (D-02)。片方だけが所有者を知る状態を
   作らない
3. `CLAUDE.md` は **once** に移す。存在すれば触らない。`--force` でも触らない
4. skill の比較は**ディレクトリ単位からファイル単位へ**。user クラスのファイルは
   比較しない。共有ディレクトリ (`.claude/hooks/`) では**自分の 3 ファイルだけ**を
   見る
5. `--force` の意味は「package クラスを新版に置き換える」の 1 つだけに保つ
   (D-03)

## 検討して採らなかった案

- **`--force` を 2 段に分ける** (`--force` = パッケージ更新、`--force-user` =
  利用者のファイルも初期化)。決定 1〜4 を入れると「利用者のファイルを捨てる」
  対象が 0 になるので、2 段目に用途が無い。フラグを増やすと、日常的に必要な
  「更新」のたびに破壊の可能性が付いてくる状態は変わらない
- **CLAUDE.md をテンプレートとマージする**。文書のマージは機械には決められない。
  once にして「必要な分は自分でテンプレートから持ってこい」と言う方が正確
- **`CLAUDE.md.new` を横に置く**。頼まれていないファイルが増える。テンプレートは
  clone 側にあるので、パスを案内すれば足りる

## 帰結

- `--claude-hooks` / `--claude-hooks-only` が、既存の CLAUDE.md や編集済み
  ルールを持つプロジェクトでも `--force` なしで通る
- チームが編集したルールは、もう衝突として報告されない (保持は元々されていた。
  報告だけが余計だった)
- **失うもの**: 「テンプレートが更新されたことを CLAUDE.md 側に知らせる」経路。
  once クラスは黙って何もしないので、テンプレートの改善は既存プロジェクトへ
  自動では届かない。これは意図した取引 — プロジェクトの規約を消さない方が重い。
  ただし**このリポジトリ自身は例外**で、原本と実体が一致していなければならない
  (design.md D-05)。実際に取り残されていたので、機械で見る
- 新しい既定ルールの有効化 (design.md D-05 候補) は**この ADR では決めない**。
  所有者モデルとは別の判断で、ADR-003 で扱う (未着手)

## 将来これを壊す形

`--force` に「利用者のファイルも置き換える」意味を足したくなったとき、
あるいは「比較は簡単なのでディレクトリ丸ごと `diff -rq` で済ませよう」と
したときに、同じ事故が戻る。**判定側だけを変えるのが特に危険** — 書き込み側は
所有者を知っているので、テストでは「保持されている」ように見え、
列挙と `--force` の側だけが壊れる (実際にそうなった)。
