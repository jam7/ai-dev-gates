# ADR-002: ゲートの判定を「HEAD 比の増分」に統一し、入口を 3 つに分ける

日付: 2026-08-29
状態: 採用

ADR 番号はリポジトリ全体で 1 系列。`docs/install/adr-001-file-ownership.md`
の次。

## 背景

既存のコードベースに後から入れられなかった。

- `check-metrics.py` は作業ツリー全体を測り、**触っていない場所の指摘でも
  コミットを止める**。pre-commit の他の checker (`check-private` /
  `check-refs` / `check-text`) は全部 `--staged` で、これだけが例外だった
- 実測 (2026-08-28): `llvm/lib/Target/RISCV` は 99 ファイルで指摘 428 件。
  `llvm/lib/CodeGen` は 368 ファイルで 1702 件。導入初日にこれら全部へ理由を
  書き終えるまで、1 コミットも通らない
- 全ツリー走査は毎コミット走る。llvm-project 全体では 4〜5 分/コミットになる
  (5ms/ファイルからの外挿)
- README 第 9 章の「入れるのは新規 PJ か、返済が終わった PJ だけ」は、
  この規模のコードベースには**入れられない**と言っているのに等しい

さらに 2 つの入口が矛盾していた (design.md D-13)。`.claude/hooks` は
何も測っておらず、SKILL.md は「既存部分はスコープ外」と書き、git 側は
既存部分で止めていた。**SKILL.md どおりに振る舞った AI は必ず落ちた**。

## 決定

1. **判定を「HEAD 比の増分」に統一する** (D-11)。3 つの入口が同じキー表記を
   使い、入口 1 と 2 は同じ判定を使う
2. **入口を 3 つに分ける** (D-10)。書く時点 = warn + 準拠メモ必須、
   コミット = block (宣言で通る)、全体 = cq-review の明示実行
3. **既存コードは触らない限り現れない** (D-12)。導入コストは 0 になる
4. **dup の corpus は触ったファイルの親ディレクトリ** (D-14)。`dup_corpus`
   で上書き可。**400 ファイルを超えたら測らず、測らなかったと言う** (D-15)
5. **dup の扱いは入口ごとに非対称** (D-16)。入口 1 は既存ペアも表示するが
   必須は増分だけ、入口 2 は新規ペアを止める

## 検討して採らなかった案

- **レガシー snapshot ファイル** (`cq-legacy.txt` に導入時のキーを機械生成)。
  増分判定なら同じ効果がファイル無しで得られる。生成物を 1 つ増やせば、
  それ自体が腐る対象になる
- **staged ファイルの全指摘を止める** (増分ではなく)。レガシー関数を 1 行
  直しただけで、その関数の宣言を要求される。返済の順番が「触ったついでに」
  から「触る前に」へ変わり、結局止まる
- **warn モード / 猶予期間**。いつまでも warn のままになる。導入問題を
  解決せず、黙らせるだけ
- **入口 2 で「AI が通したものは不問」**。人間や他ツールのコミットが無防備に
  なり、理由が git に残らない (D-16)

## 帰結

- 既存 PJ に**今日入れられる**。LLVM 規模でも導入コスト 0、コミットの計測は
  触ったファイル数に比例 (数ミリ秒〜2 秒)
- 「リポジトリ全体に未宣言の指摘が無い」という主張は**失う**。既存 PJ では
  最初から成立していないので、実質の損失は新規 PJ の保証だけ。全体像は
  cq-review が担当する (D-17)
- 「同じキーのまま悪化」(70 行 → 300 行) は捕まらない。キーが実測値を
  持たないため。両方に存在するキーの実測値も比べれば塞げる — **未着手**
- dup は corpus の外を見ない。遠い場所からのコピペは入口 3 でしか出ない
- `cq-baseline.txt` の意味は変わらない。宣言があれば通る。既存 PJ
  (image-viewer 2 件、na 4 件) の宣言はそのまま有効で、挙動は緩む方向なので
  回帰しない

## 将来これを壊す形

「全体を見た方が安全だから」と入口 1 か 2 の範囲を scope 全体へ戻すこと。
そうすると導入コストが戻り、**入れられない PJ ができる**。全体を見たいときは
cq-review を呼ぶ (D-17)。範囲を広げる前に、その PJ で 1 コミットあたり何秒に
なるかを測ること。
